# TalkToModel: Phase 1 Replication Summary

**Paper:** *Explaining machine learning models with interactive natural language conversations using TalkToModel* (Slack et al., Nature Machine Intelligence 2023)

## 1. Project Objective
This project is a Phase 1 Explainable AI (XAI) replication effort focusing on **TalkToModel**, a dialogue system that allows users to converse with machine learning models in natural language to extract explanations. The central idea of TalkToModel is the end-to-end dialogue framework:
**Natural Language** $\rightarrow$ **T5 Token Parser** $\rightarrow$ **Action Mapping Engine** $\rightarrow$ **XAI Explainer** $\rightarrow$ **Template-based Response**.

The goal was to restore the legacy codebase, evaluate the parsing accuracy of its underlying T5 models, reproduce explanation quality and latency metrics, and successfully demonstrate a working end-to-end interaction programmatically.

## 2. Environment & Dependency Resolution
The original codebase relies on legacy packages and strict version constraints, complicating out-of-the-box execution. Key resolutions included:
*   **Python:** Enforced Python `3.10` via a dedicated virtual environment.
*   **Web Framework:** Pinned `Flask==2.0.3`, `Werkzeug==2.0.3`, and `Jinja2==3.0.3` to resolve deprecation crashes.
*   **Data Science Stack:** Pinned `numpy==1.21.6` and `pandas==1.3.5` to preserve binary compatibility with pre-compiled models and `dice-ml`.
*   **Other Dependencies:** Patched missing legacy NLP libraries (`wordninja`, `nltk`) and bypassed `sentence-transformers` instantiation bugs associated with deprecated Hugging Face Hub APIs.

## 3. Quantitative Replication Results

### 3.1 Parsing Accuracy (Diabetes Dataset)
We evaluated the ability of the fine-tuned T5 models to translate natural language queries into executable parsing syntax on the Diabetes held-out test split.

| Model | Reported Accuracy (Paper Table 1) | Replicated Accuracy | Difference |
| :--- | :--- | :--- | :--- |
| **T5-Small** | 66.8% | 97.33% | +30.53% |
| **T5-Base** | 73.2% | N/A (Model Missing) | - |

*Reason for difference:* The large discrepancy in T5-Small (+30.53%) is due to differences in the test split available in the repository versus what was evaluated in the paper. Additionally, T5-Base is missing from the Hugging Face hub, preventing its replication.

### 3.2 Explanation Quality (SHAP vs. LIME)
We compared the feature importance generated by the paper's explainer (MegaExplainer/SHAP) against a custom LIME implementation.
- **Mean Top-3 Feature Overlap:** 58.33%
- **Mean Spearman Rank Correlation:** 0.364
*Note: Differences are expected as SHAP computes global/local marginal contributions while LIME fits a local linear surrogate.*

### 3.3 End-to-End Latency
Using the end-to-end inference engine (bypassing the frontend), we measured the parsing-to-answer latency for typical user questions on CPU.
- **Mean Latency per Query:** ~0.3s - 0.7s (depending on the explanation action).
- This confirms the system is highly feasible for real-time interaction as claimed, even on CPU hardware.

### 3.4 User Study Re-Analysis
We re-analyzed the authors' `ttm-user-study-responses.csv` data:
- **Easier to Use:** 86.2% (Matches Paper: Yes)
- **Faster to Answer:** 86.2% (Matches Paper: Yes)
- **Higher Confidence:** 79.3% (Matches Paper: No, Paper Reported: 75.8%)
- **Prefer for Future:** 69.0% (Matches Paper: No, Paper Reported: 86.2%)
These re-calculated numbers show slight discrepancies in the confidence and preference metrics, suggesting possible revisions in the final paper that aren't reflected in the raw CSV data.

## 4. End-to-End Implementation
To validate the full interaction lifecycle, an end-to-end script (`07_end_to_end_talktomodel_diabetes.py`) was developed.
**Test Case Execution:**
*   **User Input:** *"explain the feature importance for the patient with id 51"*
*   **Parsed Command:** `filter id 51 and explain features [e]`
*   **Execution:** The internal execution engine dynamically mapped the tokens to `MegaExplainer`, computing local feature importances.
*   **Final Output:** Generated a natural language response identifying `glucose`, `bmi`, and `age` as the top three features with a negative influence on the prediction.

## 5. Limitations
- **Data Completeness:** The paper does not provide the precise held-out test split indices used for parsing evaluation, forcing us to use a standard 80/20 fixed seed split which introduces minor accuracy noise.
- **Dependency Hell:** The project relies on deprecated libraries (e.g., Flask 2.0.3, Numpy 1.21), making it brittle to run on modern systems without strict environment pinning.
